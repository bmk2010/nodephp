Introduction

NodePHP is a small framework that lets you write HTML and JavaScript in the same file. The file gets the .np extension, and when a request comes in, NodePHP compiles it and streams the result straight back as the response.

The whole idea is to delete an entire category of work: no build step, no template language, no routing configuration. You write a file; the framework handles the rest.

Why

  • One file, one whole page. Logic and markup sit side by side — no imports, no layouts.
  • The file is the URL. about.np automatically serves /about.
  • Serverless ready. Works on Vercel with a single function — no server to provision.
  • One dependency. Just express. Nothing to install to change anything.
💡

In short: NodePHP borrows PHP's feel but is a completely different thing — it doesn't change the compile target. It only rewrites $variable into valid JavaScript.

Installation

Requires Node.js 18 or newer.

terminal 
npm install nodephp-js

To use the CLI globally:

terminal 
npm install -g nodephp-js

Quick start

1. Create a project

terminal 
mkdir mysite && cd mysite
npm init -y
npm install nodephp-js

2. Write your first file

Create index.np and put this in it:

index.np 
$name = "Muhammadhakim";
$date = "2026";

<html>
  <head>
    <title>$name — NodePHP</title>
  </head>
  <body>
    <h1>Hello, $name!</h1>
    <p>Today: $date</p>
  </body>
</html>

3. Start the server

terminal 
npx nodephp start

Open http://localhost:3000/index.np in your browser.

✅

Result: Hello, Muhammadhakim! — served with zero build tooling in the loop.

Routing

There is no router to configure. A file's position on disk is its URL.

FileRequestResult
index.np/ or /index.np200 — index.np
blog.np/blog or /blog.np200 — blog.np
blog.np/blog?page=2200 — blog.np + query
api/post.np/api/post200 — api/post.np
—/missing404 JSON
⚠️

On the local server only URLs ending in .np are accepted; everything else 404s. That's deliberate — routing should only ever reach your own files.

Syntax

NodePHP reads a file line by line. Each line is classified as one of two things: JavaScript or HTML.

Variables with $

A name starting with $ is a NodePHP variable. Full JavaScript expression syntax works inside it: =, +, ==, ===, ?? and so on.

index.np 
$name = "Alice";
$age = 30;
$isMinor = $age < 18;

<h1>$name — $age years old</h1>

if ($isMinor) {
  <p>Minor</p>
} else {
  <p>Adult</p>
}

Inside HTML, $variable is replaced with its value. Interpolation also works for property chains like $config.title and constant indices like $items[0].

JavaScript logic

A line starting with if, for, while, switch, const and friends is treated as JavaScript and executed as-is.

index.np 
$products = [
  { name: "Apple",  price: 5 },
  { name: "Banana", price: 8 }
];

<h1>Products</h1>

for ($i = 0; $i < 2; $i++) {
  $p = $products[$i];
  <div class="product">
    <b>$p.name</b> — $p.price
  </div>
}
🚨

Critical: indexing with a variable inside HTML ($items[$i]) does not work — $i survives into the interpolation and produces a SyntaxError (HTTP 500). Assign to a plain variable first, as in the example above ($p = $products[$i];). Details: Limitations.

Supported constructs

  • Variable assignment and mutation
  • if / else if / else
  • for, while, do...while
  • switch / case / default
  • try / catch / finally
  • Functions (written across multiple lines)
  • Multi-line array and object literals
  • async / await
  • res, req, console, process

Line rules

To tell HTML and JavaScript apart, NodePHP classifies each line using the rules below. Worth knowing regardless of whether you hit any of the edge cases.

LineRead as
<h1>Hello</h1>HTML — starts with <
$x = 1;JS — $var =
if ($n > 2) {JS — if + (
for more infoHTML — keyword, but no (
for ($i = 0; ...)JS — keyword + (
const a = [JS — following lines stay JS (bracket depth)
} or });JS
res.write("x");JS

Escaping rules

  • $ always means a NodePHP variable. A price like $5.00 stays literal text, but jQuery's $ will not work.
  • Literal ${...}, backticks ` and backslashes \ in HTML text are escaped automatically — they reach the browser untouched.
  • If a line contains a // comment, the lines after it are always treated as HTML. Convenient, but be aware of it.
🧩

Rule of thumb: HTML tags always go on their own line. Mixing them onto a single JS line — if ($x) { <p>yes</p> } — is a 500 error.

<?nodephp ... ?> blocks

Sometimes line-by-line detection isn't enough — a plain function call or a complex expression, for example. In those cases, everything between <?nodephp and ?> runs as pure JavaScript.

index.np 
<?nodephp
const shout = "hello".toUpperCase();
res.write("<b>" + shout + "</b>");
?>

<h1>Everything after is plain HTML again</h1>

$variable stays a variable inside the block, so you can use it both inside and after.

index.np 
<?nodephp
$items = ["Apple", "Banana", "Pear"];
?>

<ul>
<?nodephp
for (let i = 0; i < $items.length; i++) {
  res.write("<li>" + $items[i] + "</li>");
}
?>
</ul>
⚠️

Don't put ?> inside a JS string in the block — it closes the block early and everything after is treated as <?nodephp source.

<style> and <script> blocks

Their contents are emitted verbatim: no interpolation, no keyword sniffing, just raw CSS and JavaScript.

index.np 
<style>
  body { font-family: system-ui; color: #111; }
  .btn { padding: 8px 16px; border-radius: 8px; }
</style>

<script>
  let counter = 0;
  function inc() { counter++; document.title = counter; }
</script>

<h1>Hello $name</h1>
<button class="btn" onclick="inc()">Clicked</button>

If <style> or <script> appears mid-line, the rest of that line is emitted raw too, and the block continues until </style> / </script>.

Request data: file()

file("METHOD") returns an object when the request method matches METHOD, and false when it doesn't. This is the most common pattern in the language.

index.np 
if (file("POST")) {
  $name = file("POST").body("name");
  $password = file("POST").body("password");
  <h1>Welcome, $name!</h1>
} else {
  $q = file("GET").query("q");
  <p>Search: $q</p>
}

Methods

CallReturns
file("POST")object or false
.query("key")query value or null
.query()the whole query object
.body("key")JSON/form value or null
.body()the whole body object
.all(){ query, body, headers }

Full example

register.np 
if (!file("POST")) {
  <h1>Sign up</h1>
  <form method="post" action="/register.np">
    <input name="name" placeholder="Name">
    <button>Submit</button>
  </form>
  kill;
}

$name = file("POST").body("name");
$host = file("POST").all().headers;

<h1>Signed up, $name!</h1>
<p>Host: $host["host"]</p>
⚠️

Only call .body() and .query() inside if (file("...")). Calling them on the false result throws and returns HTTP 500.

Outgoing requests: connect()

Sends an HTTP request to an external URL and returns { status, ok, data, headers }. The data field is parsed into an object when the response is application/json, and left as text otherwise.

api.np 
<?nodephp
const r = connect("https://api.example.com/users", "GET");

res.json({
  status: r.status,
  ok: r.ok,
  name: r.data.name
});
?>

POST, PUT, PATCH, DELETE

The third argument is sent as a JSON body.

index.np 
<?nodephp
const r = connect("https://api.example.com/users", "POST", {
  name: "Zafar",
  age: 25
});

res.write("Created: " + r.status);
?>

Do I need await?

No. connect() is synchronous — take the result directly. Writing await also works, but it's redundant.

index.np 
<?nodephp
// no await — works fine
const r = connect("https://api.example.com/data");
res.write(r.data.job);
?>
🚨

Never call your own server. connect() blocks Node's event loop while the request is in flight. connect("http://localhost:3000/other.np") deadlocks and times out after 30 seconds. Only call external hosts.

How it works

Internally it uses worker_threads. A single long-lived worker is created, so each call does not spawn a new Node process — the overhead is negligible on Vercel. Data is handed back through postMessage, which means quotes, ${...} and backslashes survive intact. The timeout is 30 seconds.

Working with files

readFile(path)

Returns the file contents. Throws if the file is missing or empty.

writeFile(path, data)

Creates a file, or overwrites an existing one completely. If the argument is an object it's stored as JSON. Returns true on success.

index.np 
<?nodephp
writeFile("data.json", { extensions: 12, language: "en" });

const d = JSON.parse(readFile("data.json"));
res.write("Extension count: " + d.extensions);
?>
📁

Paths are resolved against process.cwd(). On Vercel the filesystem is read-only, so these two functions do not work in a serverless environment — they're intended for the local server or a long-running Node host.

Stopping a file: kill;

Forces execution to stop at that exact point. Nothing after it runs, and the response closes cleanly with a 200.

index.np 
<?nodephp
if (!file("POST")) {
  res.write("<h1>POST only</h1>");
  kill;
}

res.write("this line is never reached");
?>

This makes routing cheap: if one branch of a file should return a 404 or a redirect, you don't have to restructure the rest of it.

JSON API example

api/posts.np 
if (file("POST")) {
  $post = file("POST").body();
  res.status(201).json({ ok: true, post: $post });
} else {
  res.json({ ok: true, posts: [] });
}

If you never call res.json() or set Content-Type, the response is sent as text/html; charset=utf-8.

Deploy to Vercel

One command sets up everything:

terminal 
npm install nodephp-js
npx nodephp build
vercel deploy --prod

nodephp build produces:

structure 
api/
  index.js      <- universal handler
index.np        <- sample file, only if missing
vercel.json     <- routes every request to the handler

The includeFiles: "**/*.np" setting inside vercel.json bundles all .np files into the serverless function — without it they won't be there at runtime.

📦

On Vercel, readFile() and writeFile() do not work (read-only filesystem), and file("POST").body() needs an extra body parse step. Stick to query and headers for file(), or just return res.json().

How it works

The architecture is three steps long.

  1. Split into blocks. The file is divided into <?nodephp ... ?> blocks and the remaining "template" text.
  2. Classify line by line. Each line is identified as JavaScript or HTML. Bracket depth is tracked, so multi-line expressions are detected correctly.
  3. Execute. The result is compiled with AsyncFunction and invoked with res, file, connect and friends passed in as parameters.

Here is exactly what the first example above compiles to:

transpiler output 
var_name = "Muhammadhakim";
var_date = "2026";
  if (!res.writableEnded) { res.write(`<html>
`); }
  if (!res.writableEnded) { res.write(`  <head>
`); }
  if (!res.writableEnded) { res.write(`    <title>${var_name} — NodePHP</title>
`); }

As you can see, $name became var_name and every HTML line was wrapped in res.write(). That is the entire transpilation.

Why it's built this way

  • Simple. A single pass, zero dependencies, easy to reason about.
  • Fast. All logic runs inside a single AsyncFunction — no extra layers.
  • Safer by default. HTML text is interpolated first and then emitted as a template literal, with $, backticks and \ escaped automatically.

Limitations

These are real, verified issues — not hypotheticals. Knowing them saves time.

1. Indexing with a variable inside HTML

The most common problem. Writing $items[$i] in an HTML line leaves $i inside the interpolation and throws a SyntaxError.

✗ broken 
$items = ["Apple", "Banana"];
for ($i = 0; $i < 2; $i++) {
  <li>$items[$i]</li>      <- 500 SyntaxError
}
✓ correct 
$items = ["Apple", "Banana"];
for ($i = 0; $i < 2; $i++) {
  $item = $items[$i];            <- bind to a plain variable
  <li>$item</li>              <- clean HTML
}

Or move the whole loop into a <?nodephp ?> block, where variable indexing works fine.

2. Don't mix HTML onto a JS line

✗ broken 
if ($x) { <p>yes</p> }

HTML tags always need their own line.

3. // comments and lines with brackets

Line analysis strips // comments before anything else. As a result, a line like connect("https://...") — brackets plus // — can corrupt the state of the following HTML line. Workaround: leave a blank line after the call, or move the logic into a <?nodephp ?> block.

4. require and import don't work

A .np file is executed as the body of an AsyncFunction. There is no require and no import there — both produce a 500 error. If you need a Node module, work through process, fetch or connect(). Dynamic await import(...) does work.

5. Function calls in HTML mode don't execute

After function salom($i) { ... }, the line salom("Ali"); is read as HTML and printed as text. Put the call in a <?nodephp ?> block or on a JS line.

6. connect() blocks the event loop

Because it is synchronous, other requests can't be served while it waits. Never call a file on the same server.

7. No compilation cache

Every request re-reads and re-compiles the file. Fine for small sites, not what you want under real traffic.

FAQ

Can I use jQuery?

No. $ always means a NodePHP variable. If you need jQuery in the page, load it from a <script> block — that content is emitted raw.

Can I write prices like $5.00?

Yes. A digit after $ is not treated as a variable, so the text passes through unchanged.

What about Markdown or JSX?

Not supported. NodePHP handles plain HTML and JavaScript only. Convert Markdown to HTML in a build step if you need it.

Can I talk to a database?

Not directly, because import isn't available. But connect() lets you reach any REST API, which covers most hosted databases.

Can I cache the output?

Yes — just write res.setHeader("Cache-Control", "max-age=600"). There is no internal compilation cache, though.

Does it work inside an existing Node app?

Yes. executeNodePHP and transpileNodePHP are exported — import them from nodephp-js/lib/engine.js.
